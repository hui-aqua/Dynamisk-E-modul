Local preview

In PowerShell, change to the dataviewer directory and run:

./preview-local.ps1
# Optional alternate port
./preview-local.ps1 -Port 8080

The launcher serves the repository root so the viewer can link to local pages and sample workbooks. Keep the PowerShell window open; Ctrl+C stops the server. Python 3 is required. The HTML loads SheetJS, Chart.js, and chartjs-plugin-zoom from public CDNs, so previewing needs internet access.

For a manual preview from the repository root:

python -m http.server 8000
# Open http://localhost:8000/dataviewer/

Workbook parsing and plot data

  • Files are parsed in the browser with SheetJS. There is no application server or workbook upload.
  • findMeasurement scans the first 30 rows for a header pair: Strain, Stretch, or Extension, plus Force, Standard force, or Load.
  • Units are read from nearby rows or header labels. Lengths in metres and inches are converted to millimetres. kN and kgf values are converted to newtons. Percent strain remains in percent. Missing unit labels currently default to mm and N.
  • Sheets without a recognized force/length pair display as tables. The selected measurement sheet supplies the plotted points and CSV export.
  • The table is capped at 5,000 displayed rows; CSV export uses all valid plotted pairs.
  • Manual T_design, T_ref, and L0 edits persist across sheets in the active workbook and clear when another workbook is selected.

Stage and cycle detection

identifyStages(points) uses the editable force targets and buffers in the left panel. For design target T_design, reference target T_ref, and percentage buffers bD and bR:

designLimit = T_design × (1 - bD / 100)
referenceLimit = T_ref + (T_design - T_ref) × bR / 100

The initial stage boundaries are located from crossings of the design and reference limits. Dynamic-cycle peaks are found after smoothing a downsampled trace; the peak threshold is midway between the two buffered limits. A cycle ends at a return to the reference limit. If that return is missing before the next peak or trace end, the local trough is used; the last incomplete cycle is marked with an asterisk. These are estimates, and the instrument trace remains the source of truth.

Fit selection and engineering calculations

  • The manual range fields are one-based, inclusive. Internally the point slice uses a zero-based start and exclusive end.
  • Full cycle fits all points in the range. Loading and unloading each use one half, split at the midpoint. The quarter selector further subdivides that path; 0–100% leaves the complete path selected.
  • linearFit performs ordinary least-squares fitting of force against the selected horizontal-axis values. The reported x-intercept is -intercept / slope.
  • For stretch in mm, the adjusted length is L0 + x-intercept. Negative intercepts are allowed; E is calculated when adjusted L0 remains positive and area is available.
  • For strain in percent, E is slope × 100 / area; L0 is not used. Force points are normalized to N and cross-sectional area is in mm², so E is reported in MPa and GPa.
  • Diameter and area inputs update each other assuming a circular section. A direct area entry is used for calculation.
When changing fit or unit logic, update this guide and the end-user guide together. Keep the formulas consistent with the units shown in the result box.

Maintenance and verification

  1. Make the smallest focused change in index.html; controls and logic are inline.
  2. Run node --check on each inline script extracted from index.html to catch JavaScript syntax errors.
  3. Run the local preview and load representative workbooks with mm/N, kN, percent strain, missing Results headings, and non-measurement sheets.
  4. Confirm manual T_design, both buffers, selected stage/cycle bounds, all fit modes, area/diameter conversion, and L0 overrides.
  5. Check that Clear resets values, results, and plot controls. Verify CSV output includes every valid row.
  6. Review both HTML guides and the laboratory procedure when changing labels or calculation behavior.

Deployment

The Actions workflow at .github/workflows/deploy-pages.yml uploads the complete dataviewer directory and deploys it to GitHub Pages on every push to main. In repository settings, Pages must use GitHub Actions as its build and deployment source. The viewer depends on CDN availability at runtime.
